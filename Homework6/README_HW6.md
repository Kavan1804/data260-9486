# Homework 6 - MongoDB documents, chat memory, memory cost, file memory

For HW6 I kept extending the same root-level app from HW5. There is no separate copy of the code in this
folder; it only holds the HW6 scripts, tests, fixtures and probes. The results (RUN_LOG, raw data, METRICS,
AI_USE, verification.json, report) are in `reports/hw06/` because that is the folder the HW6 PDF asks for.

## What I added and where

| File | What it does |
|---|---|
| `backend/app/mongo.py` | PyMongo connection to `s9486_doc`; creates `listings`, `messages`, `summaries`, `episodes` with `$jsonSchema` validators and indexes |
| `backend/app/doc_schema.py` | Pydantic models for the listing document (Part 1) and the chat request (Part 2) |
| `backend/app/routers/listing_docs.py` | Part 1 CRUD at `/api/listings` |
| `backend/app/routers/memory.py` | `POST /api/chat`, `GET /api/memory/{user_id}`, `GET /api/aggregate/{user_id}` |
| `backend/app/memory_logic.py` | short-term window, session/lifetime summaries, fact extraction, embeddings + cosine top-k, prompt assembly, per-turn usage log |
| `backend/app/file_memory.py` | Part 4: loads AGENT.md and MEMORY.md, counts lines, reads the timestamp, consolidates, and runs `/memory /compact /dream /help` |
| `backend/app/main.py` | the HW5 app; I only added two `include_router` lines |
| `domain_tools/agent.py` | the HW5 Ollama adapter, now also returning Ollama's token counts and accepting `format` / `num_ctx` |
| `AGENT.md`, `MEMORY.md` (repo root) | file-based memory (AGENT.md is my HW1 file, expanded) |
| `Homework6/fixtures/` | the 30-message conversation, the 12-message demo, and the 55-line test MEMORY.md |
| `Homework6/memory_probes.yaml` | the five probe questions, what counts as a correct answer, and the 1-5 rubric |
| `Homework6/scripts/` | chat demo, experiments, probe scoring, cost, consolidation demo, AGENT.md check, file-memory chat, `verify_hw06.py`, report renderer |
| `Homework6/tests/run_hw6_tests.py` | 27 offline tests, plus 5 MongoDB tests with `--live` |

The `/api/*` routes do not use the HW4 login cookie, so I could call them from cURL like the PDF shows.

## Settings (`.env`, not committed)

| Name | What I used |
|---|---|
| `MONGODB_URI` / `MONGODB_DB` | `mongodb://localhost:27017` / `s9486_doc` |
| `OLLAMA_MODEL` | not set, so it falls back to the HW5 `LLM_MODEL` = `llama3.2:3b` |

## Things I want to point out

- **Token counts.** The prompt and completion numbers are real Ollama counts. The split between primer, summary,
  window and episodic facts is my estimate (characters / 4).
- **Embeddings.** Without an embedding model, the hash embedding only matches shared words, not meaning. It still
  found the right fact most of the time (for example "Pixel is a cat" for "what is my cat called"), but it
  cannot match synonyms.
- **Upkeep calls.** Every turn makes one extra fact-extraction call, plus a summary call every 5 user messages.
  These are logged as `aux_*` tokens and included in the cost table.
- **Probe scoring** is keyword based (rules in `memory_probes.yaml`), so anyone gets the same score, but it is
  strict. I read the answers in `raw/probe_answers_*.json` before writing my conclusions.
- **Consolidation** does not use the model. Duplicates are merged, the newest date wins a contradiction, the
  losing value is kept under "Resolved contradictions", and doubtful cases go under "Needs review". In the test
  file, `user.bedrooms` is resolved wrong on purpose (an inferred fact beats something the user said), and the
  check flags it.
- The professor folders (`Data236_DEMO6/`, `long-term-memory/`) and the PDF stay local and are gitignored, same as
  in HW5.
